# Game Design Principles

## Primary workflow principles

1. Human creative ownership
   - The user decides fantasy, taste, tone, scope, and final calls.
   - Agents present options and trade-offs; they do not silently choose the game.

2. Lore-first, game-bridge second
   - Worldbuilding remains exploratory in the world wiki.
   - This repo receives only approved game-facing slices.

3. Prototype before production
   - A documented idea is not enough.
   - Core fun must be tested through prototypes and playtests before production scale.

4. Design before implementation
   - No coding from vague chat discussion.
   - Implementation starts from approved GDDs, ADRs, control rules, and READY stories.

5. Traceability over vibes
   - Every implementation story should trace to a specific GDD rule and acceptance criterion.

6. Gates are real
   - A document existing is not the same as being good enough.
   - Gates separate blockers, concerns, accepted risks, and user decisions.

7. Scope is protected by anti-pillars
   - Anti-pillars reject attractive but harmful features.
   - MVP tests the core fun hypothesis; it is not a mini full game.

## Design lenses we will use

- MDA: Mechanics -> Dynamics -> Aesthetics.
- Verb-first design: start with what the player repeatedly does.
- Core-loop design: 30-second, 5-minute, session, long-term loops.
- Pillars and anti-pillars: falsifiable decision tools.
- Self-Determination Theory: autonomy, competence, relatedness.
- Player motivation lenses: achiever, explorer, strategist, storyteller, creator, competitor.
- Systems dependency mapping: foundation, core, feature, presentation, polish.
- Testable acceptance criteria: rules must become observable evidence.
- Playtest-driven iteration: observed confusion/fun beats speculation.

## Neon Champions-specific design posture

- HoMM3-inspired strategic clarity, not direct cloning.
- No direct magic; fantasy functions translate into cyberpunk systems, bodyware, command infrastructure, information warfare, institutions, and climate/compute constraints.
- Champions are strategic commander/identity/reputation units, not generic superheroes or spellcasters.
- Factions must be philosophies of evolution, not color teams.
- World map should preserve recognizable states while layering maintenance status, corporate concessions, climate service, feed/provenance, corridors, and Champion incidents.
- White Sky and Digital-Net systems should create playable choices, not lore wallpaper.
